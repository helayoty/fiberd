# Design: zygote

This doc explains libfiberzygote, the C library a [template](../glossary.md#template) links to become a [zygote](../glossary.md#zygote), and the line protocol it speaks with [fiberd](../glossary.md#fiberd). It is for template authors and readers of `sdk/c/template/` and `pkg/backend/proc`. Read [backends.md](backends.md) first.

## Purpose

A [fiber](../glossary.md#fiber) on the proc and runc [backends](../glossary.md#backend) is a fork of a [warm](../glossary.md#warm) process. The fork must land in the right [cgroup](../glossary.md#cgroup), carry nothing of the zygote's descriptors or environment, be confined as fiberd asked, and report ready under a deadline. A template author should get none of that wrong, so the library does it. The application initialises once, calls `fz_init` first thing in `main` and `fz_serve(3, on_fiber)` when warm, and supplies `on_fiber`, which runs in the child. In the zygote, fd 3 is the control socket fiberd hands it. On gVisor nothing forks, and a template calls `fz_gvisor_identity` and `fz_gvisor_ack` instead ([sdk/c/template/README.md](../../sdk/c/template/README.md)).

## How it works

**The contract.** `FZ_ABI_VERSION` in `libfiberzygote.h` names the ABI, and a binding checks it at build time. `fz_init` turns address-space randomisation off and re-execs, so a fiber's checkpoint can be a [delta](../glossary.md#delta) over the zygote's pages on any [home](../glossary.md#home) warmed from the same artifact, blocks `SIGCHLD` before any thread exists, and with `FIBERD_OWN_MNTNS` set takes the private mount namespace that `fz_serve` fills before READY (see below). A template that skipped `fz_init` is refused at `fz_serve`. `on_fiber` receives `fz_incarnation_t`, the record fiberd queued on the fiber's channel before the CLONE, with the [fence](../glossary.md#fence), the endpoint, the payload, the [session](../glossary.md#session) name, the generation, the kind, a 32-byte seed from the host and a [handoff](../glossary.md#handoff) fiber's TLS identity. A gVisor sandbox gets the same record through `fz_gvisor_identity`. `on_fiber` reseeds from the seed, serves, calls `fz_fiber_ready` once listening, and its return value is the exit code. Until then the child's stderr is the zygote's log, after it stderr is `/dev/null` and the seed is zeroed. In the fiber, fd 3 is the readiness pipe and fd 4 the channel (`FIBERD_CHANNEL_FD`), neither the fiber's to use. A handoff fiber keeps fiberd's channel there and serves `fz_accept` ([handoff.md](handoff.md)). Any other fiber replaces it with a pair of its own, fd 4 to read and fd 5 as the peer, which a park dumps whole. fiberd speaks on the other end, the host's end of a handoff fiber's channel or the peer of any other fiber, borrowed with `pidfd_getfd` for each exchange.

**Park and resume.** A park is cooperative, and every park of a fiber is a round of its own. fiberd queues the round on the channel (`'p'`), sends the fiber `SIGUSR1` and waits for its word, `'q'` with that round, which the template gives with `fz_quiesce` once it has stopped serving, closed its listener and closed every connection it accepted. Only then is the tree dumped. The wait is the grant's resume deadline. A fiber that does not answer in time is not parked, the park fails by name and fiberd tells the fiber so for that round (`'c'`), so a late answer meets its own carry-on and the fiber serves again. The fiber honours a carry-on for the round it answered alone, so none left by a park that gave up undoes a later park's dump. The template blocks in `fz_incarnation_wait` after its answer. After a restore fiberd writes the second record, kind `resume` with the new fence, the next generation and a fresh seed, and the template reseeds, listens again and calls `fz_fiber_ready`, which now acks with `'a'` and the fence. fiberd routes the fiber only after the ack, within the same deadline, and ends a restored tree that never acks. A dump that fails after `'q'` answers `'c'` the same way, and the template serves on as it was. refzygote ends with 122 when it gets no record, on gVisor and after a failed wait.

```mermaid
  participant Z as zygote
  participant F as fiber
  A->>Z: HIDE dir, DROP path, RUNDIR parent own
  A->>Z: PREPARE mntns
  Z->>Z: fill its own mount namespace
  Z->>A: READY
  A->>Z: CLONE fence endpoint deadline payload opts, cgroup fd and channel in SCM_RIGHTS, the 'i' record already queued on the channel
  Z->>F: clone3 into the leaf
  F->>F: scrub, read the record, confine, on_fiber
  F-->>Z: 'r' on the readiness pipe
  Z->>A: CLONED fence pid
  Note over A,Z: or ERROR fence reason, and the child is killed
  F-->>Z: exit
  Z->>A: EXITED pid exit:n or signal:n
```

**The lines.** Each message is one text line on the control socket.

| Line | From | What it says |
| --- | --- | --- |
| REBIND | fiberd, runc only | A new control socket, made inside the container's network namespace so a checkpoint finds it. It comes first |
| HIDE, DROP, RUNDIR | fiberd | Before READY, what every mount-namespace fiber covers, what it unmounts and which one run-directory entry it keeps. DROP names the resume restore root, a bind of the host's `/` ([sys.md](sys.md)). A refused one ends the zygote with an `ERROR ?` instead of READY, and fiberd fails the warm |
| PREPARE | fiberd | Ends the setup lines. `PREPARE mntns` has the zygote build the view the lines describe in its own mount namespace, once. `PREPARE none`, which the runc launcher sends, says no fiber will ask for a mount namespace. A setup line after READY, or any other line before PREPARE, is a protocol error |
| READY | zygote | The template is warm and its namespace is built. Sent once, after REBIND, the nested-namespace cap when the environment asks for it, and PREPARE. A zygote that could not prepare its namespace sends `ERROR ?` with the reason instead and ends. Every fiber of a plain proc grant asks for a mount namespace, so fiberd fails the warm and the home never reports that grant ready |
| CLONE | fiberd | The fence (at most 127 characters), endpoint, deadline, hex payload, hex session (`-` for an anonymous fiber) and options `pidns`, `mntns` and `nocaps`. The fiber finds the session as `FIBERD_SESSION`. The leaf's cgroup descriptor and then the fiber's channel ride in SCM_RIGHTS, and the channel's first message, queued before the line, is the record `'i'` with eleven NUL-ended fields. Generation, kind, fence, endpoint, hex payload, hex session, then the key, certificate, caller and caller certificate of a handoff fiber (`-` on any other), then the seed in hex. The child reads it with raw system calls into its own memory before `on_fiber` and refuses one that names another fence. The kind is `fork` and the generation 1, since a fork of the warm template starts a lineage. fiberd counts the lineage from there, and a resume brings a second record of kind `resume` with the parked generation plus one, which `fz_incarnation_wait` hands over |
| CLONED, ERROR | zygote | The new fiber's fence and pid, or why the clone failed |
| EXITED | zygote | A fiber ended, with its exit code or signal |
| DEVICE, EVICT | zygote, fiberd | An [engine](../glossary.md#engine) reports each fiber's device slice, and drops one on EVICT |

**Fork into the leaf.** `clone3` with `CLONE_INTO_CGROUP` forks the child straight into its leaf, so not one page is charged elsewhere. A kernel without it (before 5.7) gets the legacy `clone` with the same namespace flags, and the child writes itself into the leaf's `cgroup.procs` as its first act. A child that cannot ends with exit 125, and no fiber runs charged to the zygote's cgroup.

**Scrub.** Before confinement the child closes the zygote's `SIGCHLD` descriptor and every descriptor above its channel, replaces its environment with the few `FIBERD_` entries the zygote built for this fiber, starts a new session and empties its signal mask. A handoff fiber's channel is the one socket a park names external, and a resume gives it a fresh pair end at the same descriptor. Any other fiber's pair is its own, dumped whole. Its queues are empty at every park, since the fiber has taken and acked every record before it says it serves nothing, so no seed lands in the images.

**One namespace, copied per fiber.** Most of a fiber's mount work is the same for every fiber of a grant. Every mount under `/sys` is made read-only, the run directory is narrowed to this grant's entry and the HIDE directories are covered. Doing that in each child cost about 110 to 140 µs per birth, most of it the mountinfo scan and the remounts. The zygote now does it once. `fz_init` calls `unshare(CLONE_NEWNS)` and makes every mount private, before any thread exists, because with a thread already made only the calling thread would move and CRIU refuses a tree whose threads differ in namespace. It does so when `FIBERD_OWN_MNTNS` is in its environment. The proc backend sets it, and the runc launcher and an artifact build do not, since their zygote forks no mount-namespace fiber and stays in the namespace it was started in. At `PREPARE mntns` the zygote, in that namespace, makes `/sys` read-only, unmounts the DROP paths, narrows the run directory and covers the HIDE directories, then says READY. A mount-namespace fiber's `clone3` copies that namespace, so its birth adds only what is its own. Private propagation means a mount the host adds later never reaches the zygote or any fiber. The zygote itself sees other grants' run directories and the hidden paths no more than its fibers do.

| Step | Where | Why there |
| --- | --- | --- |
| `/sys` read-only, every mount under it, `/sys/firmware` covered | zygote, at PREPARE | Grant-wide. A mount added under `/sys` after that never reaches the private namespace |
| DROP (the restore root) | zygote at PREPARE, and each fiber | Grant-wide, and repeated per fiber because it is one system call and fails closed |
| RUNDIR narrowed | zygote, at PREPARE | Grant-wide. The zygote's cwd moves onto the bind and every fiber inherits it there |
| HIDE covered | zygote, at PREPARE | Grant-wide. Each path is resolved through symlinks first, so the executable inside it is still found. A HIDE directory that did not exist yet is looked for again at each birth and covered then. A HIDE directory that holds the zygote's own executable (the template cache, for a registry template) is covered with the executable bound back at its path, read-only, from a descriptor opened before the cover, since CRIU names a mapped file by a path that must resolve ([runtime-host.md](runtime-host.md)) |
| `MS_REC` `MS_PRIVATE` on `/` | each fiber | The copy is private already. The call restates it, and a refusal ends the child before anything else is mounted |
| fresh `/proc` for the pid namespace | each fiber | Its own |
| `/proc/sys`, `/proc/sysrq-trigger`, `/proc/bus`, `/proc/fs` and `/proc/irq` bound onto themselves and read-only, `/proc/scsi` and `/proc/acpi` covered | each fiber, after its `/proc` | A fiber's fresh `/proc` is a mount of its own and would cover a bind the zygote made, leaving the fiber's `/proc/sys` writable. The list is runc's for a container, and `/proc/sysrq-trigger` takes a write from euid 0 with no capability |
| capabilities dropped, user-namespace filter | each fiber | Its own |

**Confinement fails closed.** When a step fiberd asked for is refused, no fiber runs short of it. A step that fails at PREPARE, or a zygote with no namespace of its own (`FIBERD_OWN_MNTNS` unset, `fz_init` skipped, a thread before it, `unshare` refused), sets one reason, and every mount-namespace CLONE is answered with an ERROR naming it, while fibers without a mount namespace are still served. A step that fails in the child ends it before any application code, with an exit code from 110 to 125 for that step, and the CLONE is answered with an ERROR naming the step (`exit_why` in `libfiberzygote.c`).

**Nested user namespaces.** With `FIBERD_USERNS_NESTED=deny`, which the runc launcher sets, the zygote writes 0 to `user.max_user_namespaces` in its own user namespace and drops CAP_SYS_RESOURCE before READY. It refuses to do so in the initial user namespace. Each of its fibers also gets a seccomp filter. `unshare` and `clone` with CLONE_NEWUSER and `setns` onto a user namespace answer EPERM, and `clone3` answers ENOSYS so libc falls back to `clone`. On x86_64 a system call number with the x32 bit set kills the process, because the x32 table numbers these calls differently and the filter could otherwise be sidestepped through it. A checkpoint carries the filter into the fresh user namespace a restore puts the fiber in.

**Checkpoints.** A fiber's mount tree is the same shape it was when each child built it, since the copy carries the same mounts with the same flags, so a park dumps and a resume restores as before. The zygote now has a mount namespace of its own too, so its self-checkpoint (the parent for deltas) names its mounts the way a fiber's park does.

**Fork safety.** The raw clone copies one thread and runs no atfork handlers, so a lock another thread held at that instant stays held in the copy, malloc's and stdio's included. Between the clone and `on_fiber` the library allocates nothing, takes no lock and uses no stdio, and the fiber's environment is built in the parent before the clone. It reseeds no random generator either, since `srandom` takes a lock. A template reseeds its own in every new run, libc's `random()` included. That is in `on_fiber`, after a gVisor restore and when `fz_incarnation_wait` hands over a resume's record, each time from the record's seed mixed with `getrandom`, as refzygote's `reseed_rngs_from` does ([sdk/c/template/README.md](../../sdk/c/template/README.md)).

**Build flags.** On arm64, build the whole program with `-mbranch-protection=none`. A process gVisor restores keeps stale pointer-authentication keys, so a return address signed before the checkpoint fails to authenticate. CRIU 4.2.1 puts the keys back, so proc and runc restores do not trap. The C is built with `-D_FORTIFY_SOURCE=3 -fstack-protector-strong -fstack-clash-protection -fPIE -Wformat=2 -Werror=format-security` and linked with `-pie -Wl,-z,relro,-z,now`. The record's parser is Rust, a static archive from `sdk/c/template/core` linked after the C. It has no standard library and no allocator, and Rust emits no pointer authentication unless asked. CI fails if the archive needs an allocator or holds a pointer-authentication instruction. Stable Rust has no stack protector. Safe Rust makes no unchecked stack writes, and its unsafe code is the entry points the C calls and libc calls, each with an explicit length. `make fuzz` runs eight libFuzzer harnesses over the library's parsers and the reference workload under ASan and UBSan, and two cargo-fuzz targets over the Rust parser, one of them checking it against the C parser it replaced.

## Security notes and known gaps

- Fibers run as uid 0 on proc. Confinement is what stands between them and the host, and a file outside the covered paths is protected by its owner's mode alone.
- The record, a handoff fiber's key and the seed included, lives in the fiber's memory, never the zygote's, so no key lands in a template checkpoint, and the seed is zeroed at ready, at the resume's ack and at `fz_seed_forget`, so none lands in a park. A [parked](../glossary.md#park) fiber's key is in its delta, which is sealed ([artifact.md](artifact.md)). A resume's record can be written by fiberd alone. Borrowing the peer end needs ptrace rights over the fiber, which fiberd holds as root with `CAP_SYS_PTRACE`. A fiber of another grant is the init of a pid namespace where the fiber's pid names nothing, and on runc sits in another grant's user namespace besides, so `pidfd_open` answers it `ESRCH`. A fiber can write on its own peer, which forges nothing it could not do to itself.
- ASLR (address-space layout randomisation) is off, as the contract requires. What that costs is in [security.md](../security.md#known-gaps).
- A HIDE path is covered when a fiber is born. A fiber already running when the host first creates that path can read it. fiberd creates every real HIDE target before any grant warms.
- proc fibers may create nested user namespaces. The read-only `/sys` and `/proc` locks still hold inside them, so the kernel refuses a fresh writable `proc` or `sysfs`.
